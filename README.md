# BuildGuard AI — Flutter Frontend

Flutter frontend for the BuildGuard AI FYP: floor plan compliance detection
and construction risk prediction. Visual design matches the Figma
"Mobile App Landing Page Design" export (blue-700 / amber-600 palette),
and the app flow follows the SRS wireframes (Chapter 4) in the FYP report.

## What's included

- Public landing screen (matches the Figma export exactly)
- Login / Sign Up
- Dashboard, History, Profile (bottom navigation)
- Upload Floor Plan (camera or gallery, via `image_picker`)
- Project Data Entry (workers, % complete, remaining tasks)
- Analyzing screen (pipeline progress placeholder)
- Risk Analysis Result screen (violation report + risk summary)

All data currently lives in `lib/state/app_state.dart` as an in-memory
mock (`ChangeNotifier`), pre-seeded with 3 sample projects, so the whole
flow is clickable end-to-end with no backend running.

## Running it

This delivery is Dart source only (`lib/` + `pubspec.yaml`) — no native
`android/`/`ios/` folders, since those are generated by the Flutter CLI,
which isn't available in this environment. To run it:

```bash
# 1. Unzip into a folder, then inside it:
flutter create . --platforms=android,ios   # generates android/ ios/ etc., keeps lib/
flutter pub get
flutter run
```

`flutter create .` will not overwrite your `lib/` or `pubspec.yaml`
dependencies — it only scaffolds the missing platform folders.

### Camera & gallery permissions

`image_picker` needs platform permissions:

- **Android** (`android/app/src/main/AndroidManifest.xml`): add
  `<uses-permission android:name="android.permission.CAMERA"/>` if you
  want camera capture (gallery picking needs no extra permission on
  modern Android).
- **iOS** (`ios/Runner/Info.plist`): add `NSCameraUsageDescription` and
  `NSPhotoLibraryUsageDescription` with a short usage description.

## Wiring up the real backend

Per the report's software requirements (REST API / Firebase, OpenCV +
TensorFlow/PyTorch for the ML pipeline), everything currently mocked in
`AppState` is meant to be swapped for real calls:

- `login()` / `signUp()` → Firebase Auth or your REST auth endpoint
- `createProject()` → create a Firestore document / POST to your API
- `completeAnalysis()` → call your CV + ML service with the uploaded
  floor plan and project data, then populate `violations`, `riskLevel`,
  and `riskSummary` from the real response instead of the mock logic
- `UploadFloorPlanScreen` currently keeps the picked file locally
  (`XFile.path`); swap this for an upload to Firebase Storage / your
  API and store the returned URL on the `Project` model instead

`#D97706`, navy heading text `#0B1D3E`, slate body text `#475569`.
Reuse these tokens for any new screens so everything stays consistent.
